5. UI/UX Design

A multi-page Streamlit dashboard that separates prediction, analysis and evidence while keeping sensitive feedback out of persistent storage.

5.1 Decision and Scope

Selected option. SentiLingo will use a multi-page local dashboard with sidebar navigation. This is the most portfolio-oriented option: business users can analyse feedback, while evaluators can inspect model evidence and experiment traceability.

Scope correction. A production administration area and persistent prediction history would contradict the approved minimal database and privacy boundary. The dashboard therefore keeps prediction results in the current session. Its history view contains model experiments only, never stored customer messages.

5.7 Validation and Feedback States

  • Empty: explain the next action with one realistic example; do not show fake analytics.
  • Loading: disable duplicate submission and show the current operation without promising an unmeasured duration.
  • Success: show the label, confidence estimate, language variety and model version together.
  • Partial success: preserve valid CSV rows, identify invalid row IDs and allow export with error details.
  • Error: state what failed, why when known and what the user can do next; never expose stack traces.
  • Unsupported or uncertain: avoid silently forcing ambiguous, mixed-script or out-of-scope text into Neutral.

5.8 Accessibility, Arabic and Responsive Behaviour

  • All inputs have visible labels, keyboard focus and error text associated with the affected control.
  • Sentiment uses text and optional icons in addition to colour; contrast targets WCAG AA.
  • Arabic message content uses right-to-left direction, while identifiers, numbers, file names and English controls remain left-to-right.
  • The sidebar collapses at narrow widths; cards stack and result tables use a contained horizontal scroll only when necessary.
  • Charts have text summaries and readable labels; essential values never require hover.
  • Editable controls remain comfortable on touch devices and the workflow is testable at 360 px, tablet and desktop widths.

5.9 Visual and Data-Display Rules

ElementRule
NavigationStable sidebar order, one active page and no duplicate page-level actions.
SentimentAlways spell out Positive, Neutral or Negative; colour is secondary and consistent.
ConfidenceLabel it an estimate, show a numeric value only when the selected model supports it, and flag low-confidence results for review.
MetricsKeep validation and locked-test results visually separated; show per-language evidence before overall summaries.
ChartsUse directly labelled bars or tables, honest zero baselines where applicable and no decorative gauges.
PlaceholdersUse “Not evaluated” or “Not available”; never invent scores, latency or model status.

5.10 Acceptance Checklist

  • Every required page has one primary user goal and one clear primary action.
  • Single-text, CSV and evaluator flows can be completed without hidden prerequisites.
  • Prediction text is not stored and no page implies persistent customer history.
  • Empty, loading, success, partial-success, error and unsupported states are defined.
  • Arabic direction, keyboard access, contrast, responsive layout and offline operation are tested.
  • Wireframes and final screens never present illustrative data as measured model performance.
