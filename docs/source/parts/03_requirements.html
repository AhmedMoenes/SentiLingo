3. Requirements Gathering

Who SentiLingo serves, what it must do, how well it must do it, and the data and tools it needs.

3.1 Elicitation Approach

Requirements were consolidated from five evidence sources:

  1. the DEPI submission request and course learning outcomes;
  2. the approved scope and design decisions in Part 1;
  3. the research and existing-solution review in Part 2;
  4. inspection of candidate datasets, licences and sample records;
  5. delivery constraints: five weeks, limited team availability, local-first demonstration and zero budget.

Instructor confirmation is still required for the exact submission deadline and whether Azure or BiLSTM is mandatory. Until that evidence exists, neither is allowed to displace the required local release. Each requirement has an ID and a MoSCoW priority: Must, Should or Could.

3.2 Stakeholder Analysis

The primary business user is the customer-experience manager, who needs a practical way to review multilingual feedback. The DEPI instructor and evaluators have the greatest formal influence because they judge scope, evidence and delivery. The project team owns implementation decisions, while dataset providers constrain lawful use.

3.3 User Stories

IDUser storyAcceptance criteria
US-01As a CX manager, I want to upload a CSV of feedback and receive a sentiment result for every valid row.The interface validates the required text column and exports row ID, language variety, label, confidence estimate and any error message.
US-02As a support employee, I want to paste one English, MSA or Egyptian Arabic message and understand the prediction.Arabic is displayed right-to-left; the result shows label, confidence estimate, detected variety and a limitation notice.
US-03As an ML engineer, I want each experiment recorded so that I can compare or reproduce it.The record identifies data and split versions, preprocessing, model, parameters, seed, hardware, duration, metrics and artefact location.
US-04As a project evaluator, I want models compared fairly without test-set tuning.The validation leaderboard uses language-balanced macro-F1; the final report records one frozen-test evaluation after locking the configuration.
US-05As a presentation reviewer, I want the local demonstration to work without internet access.A clean-environment checklist and offline fallback reproduce representative single-text and CSV predictions.

3.4 Functional Requirements

IDRequirementPriority
FR-01Load labelled data from several sources into one schema: text, label, language, source, split.Must
FR-02Map each source's labels or star ratings to Negative, Neutral and Positive using a documented policy.Must
FR-03Remove duplicates, then create stratified train / validation / test splits with a fixed seed. The test set is frozen.Must
FR-04Preserve or assign one supported variety to each record: English, MSA or Egyptian Arabic; flag mixed or uncertain text for analysis.Must
FR-05Clean text: mask URLs, mentions, e-mails and phone numbers; strip HTML; handle emojis; lower-case Latin script.Must
FR-06Normalise Arabic: remove diacritics and tatweel; unify alef forms (أ إ آ → ا) and ى → ي; reduce repeated letters.Must
FR-07Prepare word and character inputs for classical models and subword-tokenised inputs for Transformers while preserving negation evidence.Must
FR-08Compare word TF-IDF, character TF-IDF and their combined representation.Must
FR-09Train a dummy classifier, Multinomial Naive Bayes, Logistic Regression and Linear SVM on the same frozen splits.Must
FR-10Train a BiLSTM only when the instructor confirms it is mandatory or the core schedule remains safe.Could
FR-11Fine-tune XLM-R Base as the required advanced model; attempt MARBERT on the Arabic subset only under the documented stop rule.Must
FR-12Report the mean of per-language macro-F1 as the primary validation score, with accuracy, overall macro-F1, weighted F1, per-class metrics and confusion matrices as supporting evidence.Must
FR-13Select the full configuration using validation data, then evaluate the locked configuration once on the frozen test set.Must
FR-14Record every reported experiment with data version, split version, preprocessing, model, parameters, seed, hardware, duration, metrics and artefact location; MLflow may implement this record.Must
FR-15Produce an error analysis and a table of sample predictions.Must
FR-16Predict single texts and CSV files, returning a label, confidence estimate, supported variety and validation message.Must
FR-17Provide a local Streamlit application with Arabic right-to-left display, input validation, batch export and an offline presentation path.Must
FR-18Add FastAPI, Docker or Azure deployment only after the local application, evaluation, documentation and rehearsal are stable.Could
FR-19Provide a README and a model card.Must

3.5 Non-Functional Requirements

IDCategoryRequirement
NFR-01EvaluationModel selection uses the approved validation metric and never uses final test results for tuning.
NFR-02PerformanceSingle-text and CSV latency, memory use and model size are measured on the presentation environment before a performance target is claimed.
NFR-03SecurityNo API keys or tokens in the repository; secrets come from environment variables.
NFR-04PrivacyPersonal data (handles, e-mails, phone numbers) is masked, and raw third-party data is never committed.
NFR-05UsabilityA first-time user can complete single-text and CSV prediction from labelled controls; Arabic is displayed right-to-left and sentiment is not communicated by colour alone.
NFR-06ReproducibilityFixed seeds, pinned dependencies and versioned splits; a re-run reproduces macro-F1 within ±0.01.
NFR-07ReliabilityEmpty, emoji-only, mixed-script or very long inputs never crash the pipeline.
NFR-08MaintainabilityModular code in src/, with unit tests for preprocessing and evaluation.
NFR-09TransparencyResults are reported separately for English, MSA and Egyptian Arabic, and material performance gaps are explained rather than hidden by an overall score.
NFR-10ComplianceDatasets and models are used under their licences, and all sources are cited.

Label mapping: star ratings 1–2 map to Negative, 3 to Neutral and 4–5 to Positive unless source documentation justifies a different policy. Ambiguous, mixed-sentiment and conflicting examples are flagged for review rather than silently forced into Neutral.
