Part 3

3. Requirements Gathering

Who SentiLingo serves, what it must do, how well it must do it, and the data and tools it needs.

3.1 Elicitation Approach

Requirements were gathered from five sources:

  1. the DEPI project brief, which defines the mandatory scope;
  2. the review of existing solutions in Part 2;
  3. a team workshop in which members played the stakeholders listed below;
  4. inspection of the candidate datasets;
  5. guidance from the technical instructor.

Each requirement has an ID and a MoSCoW priority: Must, Should or Could.

3.2 Stakeholders & Their Needs

StakeholderKey needs
Customer-experience (CX) managersReliable sentiment figures per language and channel; batch analysis; results they can export
Support teamsNegative feedback surfaced first, with a confidence score; works for Egyptian Arabic and Franco-Arabic
Data scientists / ML engineersA reproducible, configurable pipeline; tracked experiments; easy retraining
IT and security teamsSecure, low-cost deployment; no leakage of customer data
ManagementEvidence that the chosen model is accurate and cost-effective
DEPI instructor and evaluatorsAll brief deliverables, a sound method, and documentation delivered on time

3.3 User Stories

IDUser storyAcceptance criteria
US-01As a CX manager, I want to upload a CSV of feedback and get a sentiment label and confidence for every row.10,000 rows processed; the output adds label, confidence and language.
US-02As a support agent, I want to paste one message in Arabic, English or Franco-Arabic and see its sentiment.Result in under 1 second; Arabic shown right-to-left.
US-03As a data scientist, I want every run logged with its parameters, metrics and artefacts.Each MLflow run holds all brief metrics and a confusion matrix.
US-04As a manager, I want all models compared on accuracy and speed.A leaderboard shows macro-F1, per-language F1 and latency.
US-05As an evaluator, I want to reproduce the reported results.Following the README from a fresh clone reproduces the test metrics.

3.4 Functional Requirements

IDRequirementPriority
FR-01Load labelled data from several sources into one schema: text, label, language, source, split.Must
FR-02Map each source's labels or star ratings to Negative, Neutral and Positive using a documented policy.Must
FR-03Remove duplicates, then create stratified train / validation / test splits with a fixed seed. The test set is frozen.Must
FR-04Detect the language or script of each text: Arabic, English or Franco-Arabic.Should
FR-05Clean text: mask URLs, mentions, e-mails and phone numbers; strip HTML; handle emojis; lower-case Latin script.Must
FR-06Normalise Arabic: remove diacritics and tatweel; unify alef forms (أ إ آ → ا) and ى → ي; reduce repeated letters.Must
FR-07Tokenise text: word level for the classical and LSTM models, subwords for Transformers. Negation words are kept.Must
FR-08Build TF-IDF features with word and character n-grams.Must
FR-09Train Naive Bayes and Logistic Regression with cross-validated tuning.Must
FR-10Train a BiLSTM classifier.Must
FR-11Fine-tune at least one pretrained Transformer, multilingual and/or Arabic.Must
FR-12Report accuracy, precision, recall, F1 (macro and per class) and the confusion matrix, overall and per language.Must
FR-13Compare preprocessing strategies and models in one leaderboard.Must
FR-14Log every run to MLflow and register the best model.Must
FR-15Produce an error analysis and a table of sample predictions.Must
FR-16Predict single texts and CSV files, returning a label and a confidence score.Should
FR-17Provide a Streamlit demo that shows Arabic right-to-left.Should
FR-18Serve the best model from an Azure ML online endpoint (REST, key authentication).Could
FR-19Provide a README and a model card.Must

3.5 Non-Functional Requirements

IDCategoryRequirement
NFR-01PerformanceThe selected model meets KPIs K1–K3 (target macro-F1 ≥ 0.75).
NFR-02PerformanceOne text is scored on CPU in ≤ 20 ms (baseline) or ≤ 300 ms (Transformer).
NFR-03SecurityNo API keys or tokens in the repository; secrets come from environment variables.
NFR-04PrivacyPersonal data (handles, e-mails, phone numbers) is masked, and raw third-party data is never committed.
NFR-05UsabilityA first-time user can score a CSV file in under 2 minutes; Arabic is displayed right-to-left.
NFR-06ReproducibilityFixed seeds, pinned dependencies and versioned splits; a re-run reproduces macro-F1 within ±0.01.
NFR-07ReliabilityEmpty, emoji-only, mixed-script or very long inputs never crash the pipeline.
NFR-08MaintainabilityModular code in src/, with unit tests for preprocessing and evaluation.
NFR-09FairnessResults are reported per language, and the Arabic–English macro-F1 gap stays within 10 points.
NFR-10ComplianceDatasets and models are used under their licences, and all sources are cited.
